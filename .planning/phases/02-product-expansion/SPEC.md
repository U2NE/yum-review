# Yum Review — 관리자·탐색·사진·지역 카탈로그 확장

**상태: 사용자 승인 및 Hybrid 계획 승인 완료 — 구현 진행 중.**

## 목표

메뉴 중심 리뷰 MVP를 실제 매장 운영이 가능한 지역 음식 탐색 서비스로 확장한다. 서버 관리자와 업주가 권한 범위에 맞게 메뉴를 관리하고, 사용자는 세부 평점·사진이 있는 리뷰와 지역·음식 종류 필터를 이용한다. 초기 실매장 카탈로그는 단국대학교 죽전캠퍼스 주변 식당과 술집으로 시작한다.

## 확인된 작업 토폴로지

사용자는 아래 5개 구성 요소 전체를 진행하는 데 동의했다(clarification Round 0, 2026-09-25).

1. 서버 관리자 및 업주 권한, 관리 화면, 메뉴 CRUD와 서버 관리자 리뷰 삭제
2. 전체·맛·가성비·양 평점, 세분 정렬, 리뷰 이벤트 비참여 동의, 메뉴·리뷰 사진
3. 한식·양식·중식 등 음식 종류, 지역 및 반경 필터
4. 단국대학교 죽전캠퍼스 근처 식당·술집과 실제 메뉴로 초기 데이터 채우기
5. 음식 리뷰 서비스에 맞는 조사 기반 화면 디자인 개편

## 사용자 확인 사항

- 초기 카탈로그 사진: 사진이 확인되면 표시하되, 확인되지 않으면 생략한다. 외부 사진은 권리 확인 없이 복사해 저장하지 않는다.
- 거리 탐색: 기본 중심은 단국대 죽전캠퍼스. 장소 검색으로 중심을 변경할 수 있고, “현재 위치”는 사용자가 눌렀을 때 브라우저 위치를 요청한다.
- 2.5 평점 기준: 리뷰 작성 평점 선택 옆에 “2.5점을 보통으로 생각하고 평가해 주세요”라는 짧은 안내를 표시한다. 점수나 메뉴 평균을 2.5로 강제 보정하지 않고 실제 입력값의 산술 평균을 쓴다. 5점은 매우 드문 완벽한 메뉴로 안내한다.
- 점수 입력: 전체·맛·가성비·양 점수는 0.5부터 5.0까지 0.5점 단위로 입력한다.
- 사진 용량: 100MB 이상 파일은 거부한다. 10MB를 넘는 이미지는 저장 전에 압축/리사이즈를 시도해 가급적 10MB 이하로 보관하되, 10MB를 절대 제한으로 삼지는 않는다.
- 기존 테스트 메뉴: 기존 카탈로그의 가짜 메뉴 데이터는 실제 가게/메뉴 데이터를 넣기 전에 데이터베이스에서 제거한다.
- 디자인: 정형화된 AI 생성 화면처럼 보이지 않도록 메뉴와 지역의 개성이 드러나는 편집형 레이아웃, 실제 콘텐츠 중심의 위계와 자연스러운 한국어 문구를 적용한다.

## Hybrid 요구사항 확인 결과

- 구성 요소 5개 모두 Round 0에서 사용자 확인을 받았다. 사용자 답변에 따라 3회차에서 평점 안내를 확정했다.
- Hybrid 요구사항 엔진 재평가: 모호도 **0.1575**, 프로젝트 기준 **0.20** 이하. 메뉴 데이터 정리 범위, 0.5점 입력, 사진 최적화/최대 입력 크기, 구체적인 디자인 수용 기준을 반영했다.
- 네이버 사진 재사용 요구는 의도 자체는 분명하지만, 권리자 허락이 없는 다운로드/재호스팅은 네이버 약관과 게시자 권리 조건에 맞지 않으므로 구현 범위에서 제외한다. 메뉴 사진은 업주/관리자가 권리를 보유한 사진 또는 재사용 허가가 확인된 사진만 받는다. 이 권리 경계를 포함한 수정 사양을 승인받은 뒤에 구현한다.

## 현재 저장소와 조사

- 기존 앱은 Spring Boot 4.1.1, Spring Security 세션 인증, PostgreSQL/Flyway, React·TypeScript·Vite로 구성되어 있다.
- 현재 사용자에는 역할이 없고, 식당·메뉴·리뷰 공개 조회만 있다. 메뉴 집계 SQL은 원 점수 `AVG`를 사용하며 정렬은 인기·전체 점수 두 종류다.
- 현재 메뉴/식당에는 음식 분류, 지역, 좌표, 사진 필드가 없다. 파일 업로드 API/저장 서비스도 없다.
- 이미 적용되었을 수 있는 V1/V2 마이그레이션은 수정하지 않고 새 Flyway 버전을 추가한다. 기존 계정·리뷰 데이터는 유지한다.
- Naver Map 브라우저 화면에서 죽전 근처 실제 후보 매장(예: 호식당 죽전점, 보배반점 용인죽전점, 버거리 단대죽전점, 아지또 본점)과 메뉴 후보를 확인했다. 대량 자동 수집은 쓰지 않는다. 네이버 게시물 사진의 권리는 게시자에게 있고 외부 사이트 재사용에는 별도 권한이 필요하므로, 무단 다운로드/재호스팅은 하지 않는다.
- NAVER API 약관은 NAVER 지역정보 결과를 별도 데이터베이스로 수집·관리하는 것을 금지한다. 장소 검색 결과는 사용자 선택을 위한 실시간 UI 용도로만 취급하고 영구 저장하지 않는다. 사이트의 식당/메뉴 카탈로그는 허용된 별도 출처 또는 업주/관리자 입력 자료로 유지한다. 지도·장소 검색 API 자격 증명은 아직 제공되지 않았다.
- 화면 조사: Nielsen Norman Group의 시각 디자인 원칙은 위계·대비·균형·크기·그룹화를 사용성 기준으로 설명하며, 휴리스틱은 상태 가시성·일관성·필요한 정보의 명료성을 강조한다. 따라서 메뉴 사진과 실제 매장 정보를 중심으로 한 편집형 구성, 절제된 고유 색·서체, 명확한 점수/필터 위계로 개선한다. 보라색 그라데이션 히어로, 목적과 무관한 반복 카드, 장식용 아이콘은 사용하지 않는 방향을 제안한다.

## 토폴로지별 요구 사항

### 관리자와 메뉴 운영

- 사용자 권한에는 일반 사용자, 서버 관리자, 식당별 업주 관리자가 있다.
- 서버 관리자는 모든 식당의 메뉴를 등록·수정·삭제하고 모든 리뷰를 삭제할 수 있다.
- 업주 관리자는 연결된 자기 식당의 메뉴만 등록·수정·삭제할 수 있다. 리뷰 삭제 API와 관리 UI는 제공하지 않는다.
- 권한은 화면 표시만으로 제한하지 않고 모든 변경 API와 데이터 소유 관계에서 서버가 검사한다.
- 로컬 첫 서버 관리자 계정은 비밀을 저장소에 넣지 않는 부트스트랩 방식으로 생성하고, 생성한 ID/비밀번호를 사용자에게 한 번 전달한다. 업주 계정은 서버 관리자가 등록 사용자와 식당을 연결해 부여한다.

### 평점·리뷰·사진

- 기존 전체·맛·가성비·양 평점을 유지하고 각 축의 평균과 정렬을 제공한다.
- 전체·맛·가성비·양은 각각 0.5–5.0점, 0.5점 단위로 입력한다. UI와 서버 검증이 같은 허용 값 집합을 사용한다.
- 리뷰 폼의 별점 선택에 2.5점을 보통으로 보는 짧은 안내를 표시한다. 실제 리뷰 입력값의 산술 평균을 사용하고 5점은 완벽한 메뉴에만 주도록 안내한다.
- 정렬은 전체·맛·가성비·양 점수순과 리뷰 수순을 지원한다. 점수가 없는 메뉴는 평점순에서 뒤로 보내고, 동점은 리뷰 수와 메뉴명으로 안정적으로 정렬한다.
- 리뷰 작성 시 “리뷰 이벤트 참여 없이 작성한 리뷰입니다” 확인란을 필수로 체크해야 제출할 수 있다. 동의 기록은 저장한다.
- 메뉴에는 대표 사진 1장을, 리뷰에는 사진을 최대 5장까지 첨부할 수 있게 한다. JPEG·PNG·WebP를 허용한다. 100MB 이상은 거부한다. 10MB 초과 사진은 저장 전 압축/리사이즈를 시도해 되도록 10MB 이하로 최적화하되, 10MB 초과만으로 업로드를 거부하지 않는다. 실제 디코딩된 이미지 크기와 안전한 파일 형식을 검증한다.
- 서버가 안전한 파일명을 생성하고, 로컬 개발 환경의 업로드 디렉터리에 최적화 이미지를 저장하며 메타데이터만 DB에 둔다.
- 이미지 업로드는 인증·소유권 확인, 파일 형식/크기 검사와 안전한 파일명·경로를 사용한다.

### 음식 종류·지역 탐색

- 메뉴에는 한식·양식·중식·일식·분식·주점/안주 등 분류가 있어야 하고 복수 필터가 가능하다.
- 식당에는 주소·행정 지역과 위도/경도를 저장한다. 검색 결과에 지역을 표시하고 반경 안의 식당 메뉴를 반환한다.
- 반경은 300m·500m·1km를 제공한다. 초기 기준점은 단국대 죽전캠퍼스이며, 사용자는 장소/주소를 검색해 바꾸거나 “현재 위치” 버튼을 눌러 브라우저 위치를 사용할 수 있다. 브라우저 위치는 버튼을 누른 경우에만 요청한다.
- 장소 검색은 공식 API 결과를 실시간으로 표시해 사용자가 위치를 선택하게 한다. NAVER 지역 검색 결과는 별도 DB나 영구 캐시에 저장하지 않는다. 클라이언트 ID/Secret은 서버 환경 변수로만 받는다. 키가 없을 때에도 캠퍼스 중심과 기기 현재 위치 필터는 동작하고 장소 검색에는 설정 안내를 보여준다.
- 검색어, 분류, 반경과 정렬은 URL에 반영한다. 현재 위치 또는 장소 검색 좌표는 DB에 저장하지 않고 현재 탐색 요청에만 사용한다.

### 초기 실매장 자료

- 단국대 죽전캠퍼스 주변 음식점과 술집의 실제 정보로 예시 카탈로그를 대체·보완한다.
- 기존 테스트용 가짜 식당/메뉴 레코드를 데이터베이스에서 제거하고 단국대 죽전캠퍼스 주변의 확인된 실제 식당·술집 자료로 교체한다. QA용 가짜 메뉴에만 연결된 테스트 리뷰도 함께 제거하고, 사용자 계정 및 진짜 메뉴에 작성된 리뷰는 보존한다.
- 실제 정보를 확인할 수 없는 값은 꾸며내지 않고 비워 두거나 미확인으로 표시한다. 메뉴·가격은 업주/관리자 제공 또는 재사용이 허용된 확인 가능한 출처로 기록한다.
- Naver 지도에 업로드된 음식 사진을 사이트에 내려받아 다시 올리는 기능은 제공하지 않는다. 사진은 업주/관리자 제공 또는 재사용 허가가 확인된 이미지만 보관하고, 그 외 메뉴는 사진 없이 표시한다.
- 매장 수와 메뉴 수를 임의의 목표치에 맞춰 허위로 채우지 않는다. 단국대 죽전캠퍼스 근처에서 실제 정보가 확인되는 식당·술집만 등록한다.

### 안전한 관리 기본값

- “메뉴 삭제”는 기존 리뷰 이력과 집계를 보존하도록 공개 목록에서 숨기는 비활성화로 처리한다. 서버 관리자가 리뷰를 삭제할 때만 리뷰 레코드가 제거된다.
- 서버 관리자 첫 계정은 로컬 부트스트랩으로 만들며 비밀번호를 저장소에 기록하지 않는다. 계정 생성 후 ID와 무작위 초기 비밀번호를 사용자에게 전달하고 첫 로그인 후 변경하도록 한다.
- 업주 계정은 서버 관리자가 사용자 계정을 특정 가게에 연결해 부여한다. 권한의 최종 판정은 백엔드가 한다.

### 디자인

- 첫 화면은 메뉴 사진, 메뉴명, 식당명/지역, 전체 평점·리뷰 수를 우선 보여준다.
- 한국어에 맞는 글자 크기·행간, 일관된 그리드, 충분한 대비, 용도별 명확한 텍스트 위계를 적용한다. 브랜드 고유 타이포그래피와 제한된 색상 체계, 비대칭 편집 레이아웃과 실제 정보의 밀도를 사용한다.
- 반복되는 동일 카드 패턴, 범용 보라색 그라데이션, 불필요한 배지/아이콘, 의미 없는 인공지능식 카피를 피한다. 화면 요소는 리뷰를 탐색·비교·작성하는 목적을 지원해야 한다.
- 필터와 정렬은 실제 데이터 특성을 이해하기 쉽게 표시한다. 사진이 없는 항목은 부드러운 색면/텍스트 기반 대체 상태를 제공한다.
- 모바일 화면에서는 필터 조작·리뷰 작성·사진 확인을 편하게 하고, 과한 애니메이션과 장식은 최소화한다.

## 제안 수용 기준

1. 서버 관리자와 업주 관리자는 서로 다른 권한을 가지며, 우회 API 요청에도 서버가 권한을 강제한다.
2. 업주가 다른 식당의 메뉴를 변경하거나 리뷰를 삭제하면 거부된다. 서버 관리자만 어느 식당의 메뉴와 리뷰에도 관리 조치를 할 수 있다.
3. 메뉴 등록·수정·삭제 뒤 공개 메뉴 탐색과 평점/리뷰 집계가 갱신된다.
4. 전체·맛·가성비·양·리뷰 수 정렬을 각각 선택할 수 있으며 필터와 결합된다.
5. 리뷰 이벤트 비참여 동의 없이 리뷰는 저장되지 않고, 저장된 동의 상태를 다시 조회할 수 있다.
6. 권리 확인된 대표 메뉴 사진과 리뷰 사진을 업로드·표시하고, 잘못된 파일을 거부하며 100MB 이상 이미지를 차단한다. 10MB 초과 이미지는 자동 최적화를 시도한다.
7. 음식 종류, 지역, 선택 반경을 조합해 검색할 수 있고, 지정한 좌표에서 거리를 미터 단위로 계산한다.
8. 기존 테스트용 가짜 메뉴와 이에만 연결된 QA 리뷰가 데이터베이스에서 제거된다. 실제 계정과 검증된 리뷰는 보존된다.
9. 초기 실매장 자료는 단국대 죽전 근처의 검증된 식당·술집만 포함한다. 확인하지 않은 메뉴 가격·사진·좌표를 사실처럼 넣지 않는다.
10. 새 디자인은 조사 원칙에 따라 실제 음식 사진과 정보의 위계를 살리고 한국어 모바일/데스크톱을 모두 지원하며, 반복형 범용 AI 화면 패턴을 사용하지 않는다.
11. 기존 사용자와 실제 리뷰는 보존하고 모든 스키마 변경은 새 Flyway migration으로 적용한다.
12. 별점 선택지는 0.5점 간격이며, 입력 옆에 2.5점을 보통으로 보는 안내가 있고 계산값은 실제 리뷰의 산술 평균과 일치한다.
13. 초기 서버 관리자 ID와 무작위 비밀번호를 생성해 사용자에게 전달하며, 비밀번호는 저장소에 기록되지 않는다.

## 남은 위험과 구현 가정

- 실제 매장/메뉴의 검증 가능한 수량은 자료 출처에 달려 있다. 실정보를 검증할 수 없는 항목은 만들지 않는다.
- NAVER 장소 검색/지도 표시를 실제로 연결하려면 서버의 검색 API 자격 증명과 웹 클라이언트 지도 키가 필요할 수 있다. 키는 저장소에 넣지 않고 환경 변수로 받는다. 자격 증명이 없을 때 기본 캠퍼스 중심·현재 위치·거리 필터는 제공하고, 장소 검색에는 설정 안내를 표시한다.
- 운영자가 일반 메뉴를 제거할 때는 기존 리뷰 이력을 유지하도록 비활성화한다. 사전 카탈로그에 들어간 테스트용 가짜 메뉴와 그 QA 리뷰는 명시적 요청에 따라 실제 DB에서 제거한다.

## 비목표와 제한

- 네이버 지도 게시 사진은 권리자 허락 없이 내려받거나 재배포하지 않는다.
- 식당 전체 평점은 만들지 않는다. 평점은 계속 메뉴별로만 집계한다.
- 실제 운영 배포·결제·예약·주문·소셜 인증은 포함하지 않는다.
