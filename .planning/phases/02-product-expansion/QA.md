# Phase 02 — 구현 및 QA 기록

확인일: 2026-09-25
실행 대상: 로컬 UI/API, `yum_review_mvp` 격리 스키마, `scripts/run-qa-e2e.ps1`의 일회용 QA DB

## 자동 실행 증거

- `npm --prefix frontend run build`: 통과.
- 백엔드 `mvnw -q package`: 통과. 이 프로젝트에는 `backend/src/test`가 없어 Maven 통합 테스트/`verify` 증거는 없다.
- `scripts/run-qa-e2e.ps1`: Playwright 1개 통합 시나리오 통과(22.5초). 별도 PostgreSQL에서 가입·로그인·첫 관리자 비밀번호 변경 및 `/admin` 이동, 메뉴 탐색/필터/정렬, 미동의 제출 거부와 동의 후 2.5점 리뷰·사진, 내 리뷰 수정 폼 열기/취소, 서버 관리자 메뉴/리뷰 관리, 업주 메뉴 관리와 리뷰 삭제 거부, 모바일 메뉴를 실행했다.
- `git diff --check`: 통과.
- 로컬 브라우저: 홈 화면에서 32개 메뉴를 불러오고 매장 상세에서 볶신단국대점의 주소·메뉴 26개·네이버 지도 링크를 확인했다. 최종 전달 탭은 홈(`/`)에 두었다.

## 승인 사양 수용 기준별 상태

| # | 확인 항목 | 상태 및 근거 |
|---|---|---|
| 1 | 서버 관리자와 업주 권한 분리 | 통과. E2E에서 관리자가 등록 사용자를 가게 업주로 연결/해제하고 관리 화면을 확인했다. |
| 2 | 업주의 가게 범위 제한, 리뷰 삭제 거부 | 부분 통과. E2E에서 업주의 메뉴 작성·수정·목록 내리기와 리뷰 `DELETE` 직접 요청의 403을 확인했다. 두 번째 가게를 둔 교차 가게 변경 거부는 별도 실행하지 않았다. |
| 3 | 메뉴 변경 뒤 공개 목록/평점 갱신 | 부분 통과. 메뉴 CRUD 후 관리 목록을 확인했고 관리자의 리뷰 삭제 뒤 공개 리뷰에서 사라지는 것을 확인했다. 새 메뉴의 별점 집계 재계산 전 구간은 별도 확인하지 않았다. |
| 4 | 점수/리뷰 수 정렬 및 필터 조합 | 부분 통과. E2E에서 전체·맛·가성비·양·리뷰 수 정렬과 음식 종류·지역·반경 입력을 조작했다. 필터 URL 직접 복원과 브라우저 뒤로/앞으로는 이번 시나리오에 없다. |
| 5 | 이벤트 비참여 동의 필수 및 기록 | 통과. 미동의 저장 시 안내 오류가 표시되고, 동의 후 리뷰가 저장되는 것을 E2E에서 확인했다. |
| 6 | 이미지 권리 체크, 최적화, 100MB 경계 | 부분 통과. 메뉴/리뷰 사진 첨부·표시를 확인했다. 파일 경계값과 대용량 동시성/최적화 실패는 자동 테스트가 없다. |
| 7 | 지역·반경·장소 검색 | 부분 통과. 분류/지역/반경/current-location UI를 조작했고 NAVER 키가 없을 때 장소 검색 안내를 확인했다. 초기에 시드한 두 매장 좌표가 없어 이 데이터는 반경 결과에 나오지 않는다. |
| 8 | 가짜 V2 메뉴 정리, 실제 데이터 보존 | 로컬 스키마 통과. `yum_review_mvp`에는 새 마이그레이션이 적용되어 가짜 메뉴가 없다. 기존 DB 공개 스키마는 가짜 메뉴에 연결된 실제 사용자 리뷰 1건 때문에 V3의 fail-closed 보호가 작동해 변경하지 않았다. |
| 9 | 단국대 죽전 주변 실매장 카탈로그 | 부분 통과. 카페 1곳/메뉴 6개와 맥주·호프 1곳/메뉴 26개를 출처에 연결했다. 뚱띵이 알찜은 메뉴가 공개되지 않아 등록하지 않았다. 두 매장 모두 사진 및 건물 좌표가 없다. 볶신 메뉴는 페이지 표시 갱신일이 2026-01-20이고 현장 가격을 재확인해야 한다. |
| 10 | 한국어 반응형 편집형 디자인 | 부분 통과. 홈/메뉴 상세를 브라우저로 확인했고 E2E에서 390px 모바일 메뉴 내비게이션을 조작했다. 전 화면 시각 회귀 스냅샷은 없다. |
| 11 | 기존 계정·리뷰 보존, append-only migration | 로컬 스키마에서 V3–V5가 추가 적용되었다. 기존 기본 스키마와 실제 사용자 데이터는 이 실행에서 수정하지 않았다. |
| 12 | 반점 점수, 2.5 안내, 산술 평균 | 통과. E2E가 네 축 모두 2.5점을 저장하고 메뉴/리뷰 상세를 확인했다. |
| 13 | 초기 관리자 임시 비밀번호, 첫 변경 | 통과. E2E에서 실제 첫 로그인 비밀번호 변경 폼을 제출하고 변경 후 `/admin`으로 이동하는 것을 확인했다. 화면 갱신 중 홈으로 잘못 이동하던 경합도 수정 후 재실행에서 통과했다. 로컬 임시 관리자 비밀번호는 이 대화에서 전달했다. |

## 아직 남은 확인

- QA runner에 100MB 경계, 10MB 초과 최적화, media lifecycle 실패 복구, 기존 실제 리뷰 sentinel이 포함된 migration 테스트가 없다.
- UI 자동 시나리오는 등록된 한 테스트 케이스다. 위 표에서 “부분 통과”한 직접 API/브라우저 경로는 이후 회귀 테스트를 추가해야 한다.
- `yum_review_mvp` 시드 매장에는 주소 건물 좌표가 없어 반경 필터의 실제 결과를 보여줄 수 없다. 현재 위치 권한 흐름만 작동 확인되었다.
- `NAVER_LOCAL_CLIENT_ID`와 `NAVER_LOCAL_CLIENT_SECRET`가 없어 장소 검색 기능은 설정 안내 상태다.
- 공개 스키마 V3 적용은 사용자 계정 리뷰 1건의 보존/삭제 결정이 필요하다. 실행을 기다리는 질문에 답하기 전까지 기존 DB는 변경하지 않는다.
