# Yum Review — Next.js·Supabase 전환 및 리뷰·개인화 개선

**상태: 사용자 승인 완료 (2026-09-25).**

## 목표

메뉴 리뷰 서비스의 별점 입력을 명확하게 고치고 개인화 기능을 추가한다. 기존 Spring Boot·Vite 실행 구성을 Vercel의 Next.js App Router에 맞게 전환하고 Supabase Auth, PostgreSQL, Storage를 사용한다.

## 확인된 사용자 결정

- 별점은 5개의 별 아이콘으로 표시한다. 각 별의 왼쪽/오른쪽 절반을 선택해 0.5점 단위로 입력한다. 10개의 별 모양을 나열하지 않는다.
- 리뷰에서는 전체 별점만 필수다. 맛·가성비·양은 선택 입력이고, 선택한 반쪽 별을 다시 누르면 그 세부 평가를 지운다.
- 전체 별점은 리뷰와 메뉴 카드에서 가장 두드러지게 표시하고, 맛·가성비·양은 보조 정보로 작게 보여준다. 보조 평가가 없는 경우 `미평가`로 표시한다.
- 사진 권리 확인 체크 문구는 리뷰 사진 첨부와 메뉴 사진 편집 양쪽에서 없앤다. 기존의 “이벤트 참여 없이 작성한 리뷰” 필수 동의는 유지한다.
- 홈의 현재 `기록의 기준` 마감 섹션을 제거한다. 현재 UI 코드에는 탭이 아닌 `closing-note` 섹션으로 구현되어 있다.
- 로그인 사용자는 다른 사람의 리뷰에 좋아요를 누르거나 취소할 수 있다. 본인 리뷰에는 좋아요 기능을 제공하지 않는다.
- 로그인 사용자는 메뉴를 `먹어보고 싶은 메뉴`에 저장/해제할 수 있다.
- 홈에서 `내가 리뷰한 메뉴`, `먹어보고 싶은 메뉴`로 필터링한다. 현재 검색어, 음식 종류, 지역·반경, 정렬 필터와 함께 사용할 수 있다.
- 회원정보는 이름(표시 이름)과 비밀번호만 수정한다. 이메일은 로그인 주소로 유지하며 이 화면에서 변경하지 않는다.
- 배너의 “다음 한 끼를 메뉴부터 고릅니다” 문구와 현재의 AI처럼 느껴지는 홍보성 카피를 없애고, 제품 목적을 직접 설명하는 자연스러운 문구와 고유한 한입 로고를 만든다.
- Vercel 저장소 연결은 변경하지 않는다. 사용자가 준 Vercel 토큰은 저장소에 기록하지 않고 Vercel 프로젝트 환경변수 설정에만 사용한다.

## 범위

### 1. 별점 및 리뷰

- 평가 컨트롤은 접근성 있는 5개 별 아이콘을 사용하며 각 별의 절반을 선택할 수 있다. 전체 점수 범위는 0.5–5.0이다.
- 전체 점수만 필수이며 맛·가성비·양은 `NULL` 허용이다. 댓글은 기존 1,000자 제한을 유지한다.
- 기존 리뷰의 점수와 집계는 보존한다. 세부 평균은 해당 항목을 평가한 리뷰만 대상으로 계산한다. 메뉴 전체 평균은 전체 점수의 실제 산술 평균이다.
- 이벤트 비참여 동의는 새 리뷰 작성 시 계속 필수다. 기존 리뷰에 기록이 없으면 동의한 것으로 변환하지 않는다.
- 별을 같은 값으로 다시 누르면 그 입력값을 해제한다. 키보드 조작, 포커스 표시, `aria-label`로 같은 동작을 사용할 수 있다.

### 2. 좋아요·찜·필터

- 리뷰 좋아요는 `(user_id, review_id)`별 하나만 저장하고, 총 개수와 현재 사용자의 선택 상태를 보여준다.
- 본인 리뷰에 대한 좋아요 생성은 UI뿐 아니라 DB 정책에서도 거부한다.
- 메뉴 찜은 `(user_id, menu_id)`별 하나만 저장하며 목록은 해당 계정에만 공개한다.
- 홈 필터 `내 리뷰`, `찜한 메뉴`는 인증된 사용자의 데이터로만 조회하고 기존 검색·종류·지역·거리·정렬 조건과 조합한다. 비로그인 사용자가 개인 필터를 선택하면 로그인 흐름으로 안내한다.

### 3. 계정 설정과 사진

- 계정 설정 페이지에서 표시 이름과 비밀번호를 저장·변경한다. 이름과 새 비밀번호의 서버/DB 검증 오류를 이해하기 쉬운 한국어로 표시한다.
- 리뷰·메뉴 사진 업로드 화면에서 권리 확인 체크박스와 그 확인값 전송을 제거한다. 사용자에게 없는 동의를 있었다고 기록하지 않는다.
- 기존 사진 입력 제한을 유지한다. 100MB 이상은 거부하고 10MB 초과는 가능한 한 압축/최적화한다.
- 배포 함수의 요청 크기 제한을 피하도록 브라우저에서 Supabase Storage로 직접 업로드한다. 업로드 정책은 Supabase Auth 사용자와 메뉴 소유권/관리자 권한으로 제한한다. 이미지 공개 읽기는 앱 표시 목적의 경로에만 허용한다.

### 4. 화면과 브랜드

- 홈의 `closing-note` / `기록의 기준` 섹션을 제거한다. 리뷰 작성 폼의 비이벤트 리뷰 동의는 유지한다.
- 히어로 문구는 짧고 설명적인 한국어로 바꾸며, 광고성 약속이나 AI식 상투 문구를 쓰지 않는다.
- 음식·리뷰 브랜드에 맞는 고유한 벡터 워드마크/심볼을 제작한다. 메뉴 탐색과 별점 이해를 돕는 요소만 사용하고, 새 로고가 메뉴 사진이나 리뷰 내용을 가리지 않게 한다.
- 기존의 모바일 우선 레이아웃과 한국어 표시를 유지한다.

### 5. Next.js·Supabase·Vercel

- Vercel 저장소 루트에 Next.js App Router 애플리케이션을 둔다. 루트에서 `next build`가 실행되어야 한다.
- 기존 로그인·가입·로그아웃, 메뉴/식당 탐색, 관리자·업주 권한, 리뷰 작성/수정/삭제, 사진, 기존 검색·거리·종류 필터와 UI를 새 런타임에서 계속 제공한다.
- Supabase Auth를 계정 인증의 기준으로 하고, PostgreSQL에 프로필·역할·식당·메뉴·리뷰·사진 메타데이터·좋아요·찜을 저장한다. Supabase Storage를 사진 저장소로 사용한다.
- `@supabase/ssr`의 서버/브라우저 클라이언트 구분을 사용한다. 게시 가능한 키는 브라우저 설정에만 두고, 비밀 키는 server-only 환경변수에만 둔다. 사용자의 일반 데이터 읽기/쓰기는 Auth 사용자 JWT와 RLS를 사용한다.
- 공개 스키마 테이블과 Storage 객체에 최소 권한을 적용한다. 관리자/업주 쓰기 권한, 리뷰 작성자 권한, 본인 정보/찜 권한, 타인 리뷰 좋아요 권한을 Postgres RLS와 필요한 고정 `search_path` 보안 함수로 강제한다.
- Supabase SQL 변경은 `supabase/migrations/`에 추가하며 기존 프로젝트 데이터와 인증 설정을 검사하기 전에는 초기화·삭제 작업을 하지 않는다.
- 기존 계정·식당·메뉴·리뷰·사진 데이터를 가능한 한 보존한다. 기존 BCrypt 비밀번호 해시는 Supabase Auth가 지원하는 해시 형식이면 보존해 이전하고, 불가능한 계정이 발견되면 해당 계정을 버리거나 임의 비밀번호로 재생성하지 말고 이행을 멈춰 사용자에게 처리 결과를 알린다.
- Vercel Production에만 앱이 필요로 하는 Supabase 환경변수를 설정한다. 별도 Supabase 스테이징 프로젝트가 없으므로 Preview/Development를 실제 데이터 프로젝트에 연결하지 않는다. Vercel 프로젝트·Git 연결·Production Branch는 바꾸지 않는다.
- 토큰과 비밀 키는 코드·설정 파일·빌드 로그·Hybrid 결정 기록에 포함하지 않는다. Supabase DB 비밀번호는 Vercel 런타임 환경변수로 사용하지 않는다.

## 수용 기준

1. 전체 및 세부 점수가 5개 별 아이콘의 반쪽 단위로 입력되고, 재클릭 해제가 동작한다. UI·DB 평균이 0.5점 값을 정확히 보존한다.
2. 전체 점수는 필수지만 세부 점수는 비워 저장할 수 있다. 평가되지 않은 세부 점수는 집계에서 제외되고 UI에 미평가로 표시된다.
3. 사진 권리 체크 UI/검증이 리뷰·메뉴 사진 경로에서 제거되고, 이벤트 비참여 동의는 리뷰 작성에 계속 필요하다.
4. 홈 `기록의 기준` 영역이 사라지고 새 브랜드/배너 문구가 모바일·데스크톱에서 읽기 쉬우며 메뉴와 별점 콘텐츠를 우선한다.
5. 인증 사용자는 타인 리뷰에 한 번 좋아요를 누르고 취소할 수 있다. 본인 리뷰와 비인증 쓰기는 DB RLS에서도 거부된다.
6. 메뉴 찜 저장/취소, 개인 목록, `내 리뷰`/`찜한 메뉴` 필터가 구현되고 다른 검색·음식 종류·지역·반경·정렬과 함께 작동한다.
7. 설정 화면에서 표시 이름과 비밀번호를 갱신할 수 있고 이메일은 수정할 수 없다. 다른 사용자 프로필/비밀번호 데이터는 열람할 수 없다.
8. 루트에서 Next.js 빌드가 성공하며 이전 핵심 플로우가 Next.js·Supabase 런타임에서 유지된다.
9. 모든 공개 테이블/Storage 규칙에 RLS와 필요한 인덱스·최소 권한이 적용된다. 직접 API 호출로 권한을 우회할 수 없다.
10. 기존 사용자·리뷰·카탈로그 데이터를 삭제하지 않고 매핑/이관할 수 있다. 이관을 보장할 수 없는 행은 조용히 건너뛰지 않고 이유와 영향 범위를 보고한다.
11. Supabase publishable URL/key와 server-only secret key가 Vercel Production에 설정되고 Vercel 저장소 연결은 그대로다. Repository diff, 런타임 로그, provenance 기록에 비밀 값이 없다.

## 비목표

- Vercel Git 연결 또는 도메인 변경.
- 공개 리뷰 이벤트 동의 제거.
- 이메일 주소 변경 기능.
- Supabase/Vercel 대시보드의 초기화, 기존 데이터 삭제, 인증 확인 설정 변경.
- NAVER 게시 사진의 동의 없는 재게시.

## 기술 근거

- Supabase Next.js 서버 인증: [공식 SSR 가이드](https://supabase.com/docs/guides/auth/server-side/nextjs)
- Supabase 행 수준 접근 제어: [공식 RLS 가이드](https://supabase.com/docs/guides/database/postgres/row-level-security)
- Supabase 기존 비밀번호 해시 이전: [Auth0 이전 문서의 BCrypt 해시 import 방식](https://supabase.com/docs/guides/platform/migrating-to-supabase/auth0)
- Next.js 서버 데이터 변경/엔드포인트: [Server Functions](https://nextjs.org/docs/app/getting-started/mutating-data), [Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)
- Vercel 환경변수는 새 배포부터 반영되고 환경 범위를 구분한다: [공식 환경변수 가이드](https://vercel.com/docs/environment-variables)
